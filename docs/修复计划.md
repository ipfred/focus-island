# 稳定性与安全修复计划

分支：`fix/stability-security`（基于 `master` 的 2.9.0）

本文档列出代码审查中发现的问题，按重要性排序，并标注本分支的处理状态。末尾给出面向后续迭代的完善建议。

状态说明：✅ 本分支已修复；⏳ 已记录，留待后续迭代。

## 一、高优先级

### H1 备忘录编辑器 XSS ✅

- 位置：`src/panel/MemoEditor.vue`（粘贴处理、`onMounted` 中写入 `innerHTML`）
- 问题：粘贴 HTML 时只过滤字符串 `<script`，`<img onerror>`、`<svg onload>`、`javascript:` 链接都能通过；内容保存后每次打开备忘录都会执行。同时 `tauri.conf.json` 中 `csp: null`，注入的脚本可以调用 `invoke`、shell open、剪贴板读取等能力。
- 修复：
  - 新增 `src/utils/sanitizeHtml.ts`，基于 DOMPurify 清洗 HTML，并禁用 `style`、`form`、`iframe` 等标签。
  - 粘贴内容和从存储加载的内容都先清洗再写入编辑器。
  - 在 `tauri.conf.json` 中配置 CSP：脚本只允许同源；图片允许 `data:` 和 https；音频允许网络电台流地址；开发环境额外放行 Vite HMR 的 websocket。

### H2 数据持久化可能丢数据 ✅

- 位置：`useTasks` / `useSettings` / `useMemos` / `useTaskGroups` / `useDailyStats` / `useAchievements` / `useRadio`
- 问题：
  1. 直接覆盖写文件，不是原子操作。写到一半退出或崩溃会留下损坏的 JSON。
  2. 读取或解析失败时静默回退到空数据，下一次改动就会把空数据写回，原数据彻底丢失。
  3. 多次保存并发执行，先发起的写可能后完成，磁盘上留下旧数据。
  4. 没有防抖，拖动滑块等操作会触发大量写盘。
  5. 跨窗口同步用 `setTimeout(50)` 屏蔽回写，这 50ms 内本地的真实修改会漏存。
  6. `useSettings` / `useRadio` 用 `loaded` 判断是否已加载，而 `loaded` 在加载完成前一直为 false，启动阶段会重复加载。
- 修复：新增 `src/composables/persistence.ts`，七个模块统一接入：
  - 写入先写 `.tmp` 再 `rename`，保证原子性；
  - 每个文件一条写入队列，保证串行；
  - 300ms 防抖；
  - 读取或解析失败时，先把原文件备份为 `*.corrupt-<时间戳>`，备份失败就禁止写入，避免覆盖唯一副本；
  - 用"上次快照 JSON"判断数据是否真有变化，取代 `setTimeout` 方案；
  - 用 `loadPromise` 保证每个窗口只加载一次。
- 设置的跨窗口同步也改走同一机制，删除 `applyExternalSettings` 和 `suppressEmit`。

### H3 统计与成就日期使用 UTC ✅

- 位置：`useDailyStats.ts`、`useAchievements.ts` 中的 `toISOString().split('T')[0]`
- 问题：UTC+8 时区 0–8 点完成的番茄会记到前一天，连续打卡天数和"晨光者"成就都会受影响。`useTasks` 用的是本地日期，两边口径不一致。
- 修复：新增 `src/utils/date.ts`，统一使用本地日期，"昨天"改用日历日减 1 计算。
- 已知影响：历史数据已经按 UTC 日期存储，无法回溯修正。

## 二、中优先级

### M1 全局快捷键依赖 300ms 节流防重复 ✅

- 位置：`src/composables/useShortcut.ts`
- 问题：Tauri v2 的快捷键回调在按下和松开时都会触发，现在靠 300ms 节流避免面板开了又关。
- 修复：只在 `event.state === 'Pressed'` 时切换面板，删除节流。

### M2 计时器设置 watcher 重复注册且生命周期错误 ✅

- 位置：`src/composables/useTimer.ts`
- 问题：每个调用 `useTimer()` 的组件都会注册一个监听时长设置的 watcher。这些 watcher 绑定在调用方组件的作用域上，组件卸载后就失效。
- 修复：放到独立的 `effectScope` 中，整个应用只注册一次。

### M3 死代码与无用依赖 ✅

- 前端从未调用的 Rust 命令：`get_mouse_position`、`set_island_height`、`get_window_position`、`show_panel`、`set_island_visible`、`get_screen_info`。删除，并取消 `animate_panel_open` 的命令注册（函数本身在 Rust 内部还在用）。
- 没有被引用的组件：`src/components/LineHide.vue`、`src/components/TaskList.vue`。
- 没有使用的 `useTasks().todayStats`，而且它的 `totalPomodoros` 实际是所有任务的累计值，不是今天的。
- 没有被引用的依赖 `@tauri-apps/plugin-app@^2.0.0-alpha.1`。

### M4 项目文档与代码不一致 ✅

- `CLAUDE.md` / `AGENTS.md` 中以下描述与代码不符：
  - 数据目录写成 `pomodoro-island/`；
  - 任务分类还按 `category` 描述，实际已改用 `dueDate`；
  - 状态广播写的是每 500ms，实际是状态变化时触发；
  - 面板动画写的是由 Rust 线程逐帧插值，实际已由前端驱动；
  - `onPhaseDoneCallback` 写在 `Island.vue`，实际注册在 `useTimerBridge`。
- 修复：按实际代码更新文档，并补充持久化层和 CSP 的说明。

### M5 空闲检测量的不是系统空闲 ⏳

- 位置：`src/composables/useIslandState.ts`
- 问题：`useIdle` 只监听灵动岛 WebView 内的事件，而这个窗口大部分时间是鼠标穿透的，实际衡量的是"多久没碰灵动岛"。
- 建议：在 Rust 端用系统 API 获取空闲时长（macOS `CGEventSourceSecondsSinceLastEventType`，Windows `GetLastInputInfo`），通过命令或事件提供给前端。属于架构级改动，本分支不做。

### M6 计时器运行在隐藏窗口中 ⏳

- 问题：计时核心运行在大部分时间隐藏的 panel WebView 中，可能被系统节流（App Nap、WebView2 后台节流），导致到点通知延迟。计时状态也没有持久化，重启后进行中的番茄会丢失。
- 建议：把计时状态机迁到 Rust，作为唯一状态源，两个窗口都只负责展示。

### M7 停靠模式鼠标轮询开销 ⏳

- 问题：停靠模式下每 120ms 调用一次 `is_mouse_over_window`；Linux 上每次调用都要 `XOpenDisplay`/`XCloseDisplay`。
- 建议：鼠标离屏幕顶部较远时降低轮询频率；Linux 上复用同一个 Display 连接。

### M8 备忘录编辑器的其他问题 ⏳

- 卸载时无论有没有修改都会触发保存，可能改变 `updatedAt` 和列表排序。
- 自动保存延迟 10 秒，期间退出应用可能丢失修改。
- 图片以 base64 内联存储（单张最大 2MB），文件和跨窗口同步的负载都很大。
- `document.execCommand` 已被废弃。

## 三、低优先级 ⏳

- `TodoPage.vue`（2156 行）、`MemoEditor.vue`（1428 行）、`TaskDetailPage.vue`（1100 行）过大，需要拆分。
- `TodoPage.vue` 的点击外部关闭在 window 和根节点上各绑了一次。
- 多个页面重复手写"监听器挂载/卸载"逻辑，应抽成 composable。
- `set_island_size` / `set_island_custom_size` 中的居中计算重复。
- 开机自启参数 `--hidden` 没有被处理。
- 更正此前的审查结论：`autoLaunch` 默认值虽然是 `true`，但 `load()` 会用系统实际状态覆盖它，首次启动不会擅自开启自启。这一条不算问题。

## 五、后续迭代建议

下面这些是持续加功能之前最值得先补的基础设施，按投入产出比排序。

1. **建立测试与 CI 门禁**
   - 用 Vitest 覆盖纯逻辑：计时器状态机、任务日期分类、持久化层（mock fs）、统计汇总。用 `cargo test` 覆盖代理字符串解析。
   - 新增 PR workflow：`vue-tsc`、`vite build`、三平台 `cargo check` 和 `clippy`。现在只有发布 workflow，回归只能靠手测。
   - 引入 ESLint、Prettier、rustfmt，统一代码风格。
2. **集中定义 IPC 契约**
   - 事件名（`timer-state-update`、`tasks-updated` 等）和 payload 类型现在以字符串散落在各文件里，加功能时很容易拼错，类型也对不上。
   - 建议集中到 `src/ipc/` 统一定义，Rust 命令可用 tauri-specta 生成 TS 类型。
3. **数据层演进**
   - 在 `persistence.ts` 基础上为每个文件加 `schemaVersion` 和迁移函数，代替 `useTasks` 里那种零散的字段兼容逻辑。
   - 补上数据导出/导入（ZIP 打包）和定期自动备份。
   - 备忘录图片和统计历史持续增长后，考虑迁到 SQLite（`tauri-plugin-sql`）。
4. **核心逻辑下沉到 Rust**
   - 计时器、系统空闲检测、系统通知（`tauri-plugin-notification`）放到 Rust 端，消除隐藏窗口节流和双窗口状态不一致的问题。
   - 这是后续做"勿扰联动"、"专注历史日志"等功能的前提。
5. **前端结构**
   - 拆分超大组件，沉淀通用 UI 组件（步进器、对话框、下拉菜单）。
   - `PanelApp` 中的 `currentView` 改成视图注册表，新增页面时不用改主组件。
   - 编辑器换成 Tiptap，摆脱 `execCommand`。
6. **设置校验**
   - 用 valibot 或 zod 校验设置并限定数值范围，防止手改文件或旧版本数据导致时长为 0、出现 NaN 等异常。
7. **可观测性**
   - 接入 `tauri-plugin-log` 落盘日志，用户反馈问题时可以直接附上日志。
   - 目前大量 `.catch(() => {})` 会吞掉错误，应至少打印一条日志。
8. **平台与发布**
   - 做 macOS 签名和公证，从根本上解决更新后被 quarantine 的问题，而不是靠修复命令。
   - 补充 Wayland、多显示器、刘海屏的适配。
   - `AGENTS.md` 和 `CLAUDE.md` 内容完全重复，建议保留一份，另一份引用它，避免以后再次不一致。
